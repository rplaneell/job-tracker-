# Prior art research and safety checks

Date: 2026-11-17

## Method

Search results gave candidates. Each one was checked from the outside first (owner type, age, stars, forks, license, last update). Only the best candidate was downloaded, into its own empty folder outside this project, with git hooks switched off and nothing executed. It was then scanned by reading files and searching for danger signs.

## JobSync scan results (Gsync/jobsync)

- No install hooks (`preinstall`, `install`, `postinstall`, `prepare`) in `package.json`.
- No `eval`, `new Function` or `child_process` use in the source. Base64 appears only in its own encryption code.
- Shell scripts contain no download and run patterns. They only check the app's own container.
- Outbound hosts are the expected ones: AI providers, the three job board APIs, GitHub.
- No committed `.env` files or key shaped strings.
- The two odd looking hits were harmless: an example URL inside an AI prompt, and a wiki sync script reading a CI token from its environment.

This is a static scan, not a guarantee. Nothing from JobSync was installed or run, and it is not a dependency of this project.

## What we take from it (ideas only, no code copied)

- Lever has a separate EU host for both the API and public links. Our design already handles this with the `eu:` prefix.
- It keeps one folder per board type (greenhouse, lever, ashby) plus a shared mapper, which matches our adapter layout.
- It stores a board "token" per company, the same as our `sources.yaml`.

## Why we still build our own

JobSync is a Docker app with Prisma, SQLite, NextAuth and AI key management. Our plan uses Supabase, GitHub Actions and a free hosted dashboard, and adds a Europe focused rules file, a daily email and later practice tools. Adopting it would mean replacing most of it.
